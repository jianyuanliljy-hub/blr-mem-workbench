# 交付与人工检查

本次为 `0.1.0.dev1` 检查预览版。Windows 包自带 CPython 3.13.5、科学计算依赖和 Tcl/Tk；macOS 包为 Apple Silicon 原生 `.app`。完整解压后即可使用，检查者无需配置 Python 环境。

## 最短检查路径

1. Windows 双击 `BLRWorkbench.exe`；Mac 双击 `BLR MEM Workbench.app`。选择一维或二维。
2. 初次检查可把“噪声比例”设为 `0.05`，生成一个样本。原来的无噪声默认值保持为 0。
3. 切到 MEM 页，数据路径已经填好，直接运行默认 MEM。
4. 切到检测与报告页，检测反演结果，生成并打开报告。
5. 查看二维结果时，区分最终一阶条件、浮动默认图像稳定性和优化历史。稳定性 WARN 会明确保留。

如果只想先看效果，直接打开 `examples/1D/report/report.html`、`examples/2D/report/report.html`。已有 144 例分析在 `validation/report.html`，附原始协议、逐对象 CSV 和汇总 JSON。

无噪声拟合需要显式填写 C、L 绝对误差下限；文档示例为 `0.05`、`0.03`。这两个数字是本次数值拟合的权重假设，可能影响恢复结果，不表示数据被加入噪声。

## 此次修改的范围

常用参数从整页 JSON 改为带单位表单，高级 JSON、保存和载入预设共用同一份配置。生成数据和拟合结果自动填入下一步，错误返回清晰原因，报告先展示中文摘要，再展示关键图和完整记录。Windows 只使用一个界面 EXE 和共享运行时，没有增加大型界面框架或机器学习依赖。

扫描续跑修复了两处软件错误：旧检测收据可能掩盖新的 FAIL；已完成点的结果目录缺失时仍可能被计为完成。现在每次续跑会核对结果并独立重检，保留原收据，发现不一致时给出具体原因。已有科学目标函数、求解算法、默认超参数和验收阈值保持原样。

报告新增统一色标的二维真值对照、时延/速度边缘响应、残差分布、迭代历史和低响应区默认变化诊断。低于峰值 1% 的分区仅供解释，不参与 PASS/WARN/FAIL 判定。

Windows 检查者可双击 `Diagnose.cmd`，它会运行两维界面流程，在 `%TEMP%` 下新建测试数据和收据。命令行用 `blr-rm.cmd`。默认输出目录为用户主目录下的 `BLR_MEM_outputs`，也可在界面选择其他位置。

Mac 应用使用临时签名，未经过 Developer ID 签名或 Apple 公证。如果系统阻止打开，请按系统提供的开发者应用打开流程处理。

## 科学结论的边界

旧的 144 例合成结果已经只读复核，指标与状态一致，没有覆盖或重新求解。最终一阶条件均通过；二维 72/72 保留浮动默认图像稳定性 WARN，其中 64/72 的历史有中间优化失败标志。当前不足以宣称所有二维数值问题解决、真实 AGN 验证完成，或默认参数对任意数据都最优。

本轮低响应诊断显示：二维低响应区总响应量中位数约占 0.41%，对均方对数默认变化的贡献中位数约 84.3%。这解释了部分警告来源，不能据此删除警告或证明强响应区域不再变化。
