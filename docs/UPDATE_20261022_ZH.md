## 目录和命名

继续沿用仓库的 `1D/`、`2D/`，不复制两套容易分叉的求解器。Windows 构建保留 `BLRWorkbench.exe`、`blr-rm.exe`，并实际加入已有启动代码支持的五个入口：

| 用户功能 | Windows 入口 | 共享代码 |
|---|---|---|
| 单组模拟数据 | GenerateData.exe | data.py |
| 批量模拟数据 | BatchGenerate.exe | data.py |
| 优化主程序 | MEMOptimizer.exe | solver.py |
| 检测器 | Detector.exe | detector.py |
| 数据分析 | Analysis.exe | report.py / benchmark.py |

入口无参数时打开相应 GUI 页；命令行传参数时调用相应业务。入口共享同一个运行时目录，不是可以单独移动的单文件 EXE。一维/二维在界面选择；相应默认配置保留在各自文件夹。此源码更新不等于已经完成二进制构建验收。

## 已修复的二维优化问题

1. 每个坐标循环结束的状态检测，原先三次调用完整目标函数/梯度；改成一次，数学目标不变。不能据此声称整体快三倍，因为主要时间也在 L-BFGS 内。
2. 内层固定默认图未满足 TEST 和相对梯度条件时，停止并保留未收敛状态，不再直接改变默认图开始下一层。
3. 内层收敛且默认图变化已达配置阈值时提前结束，避免无意义的后续层。

原版已有的独立前向检查、结果身份验证、纯扫描不自动选优和真值隔离设计值得保留。检测器不应因为优化器返回 success 就宣布科学恢复成功。

## 与之前程序的重要区别

此仓库二维目标是原始卡方求和减三个像素熵求和；不是后期的分别约化目标。当前 alpha_map=1000、alpha_c=200、alpha_lbg=10 只是此实现的例子。不能把归一化实验中的 0.2、1200、0.02 直接替换进来。

一维是固定默认图的联合优化，并用对角尺度预处理；二维是坐标分块加浮动默认图。这并不是同一目标的一维/二维简单切换。暂不强行统一，以免悄悄改变算法。

## 五项需求的真实状态

- 无噪声生成：用 `generate_clean.json`，保存 truth.npz 和真值图。无噪声不等于没有卷积或没有物理背景；其误差为零，反演必须显式给 error-floor。
- 批量生成：已有 batch、独立种子及续跑协议。
- 优化：已有，做了上述保守修复；尚未接入旧应用的 JAX/Numba、season gap 专用参数与仪器展宽。
- 检测：已有输入、前向、目标/梯度、默认图稳定和真值指标。默认优化与纯扫描走同一检测。扫描点写完不等于所有点收敛；跨 alpha 不用 Q 最小作为选优依据。
- 分析：已有单例报告与 144 例冻结协议。仓库附带的旧实验收据仅代表旧实现，不能当成本轮修改的验证。本轮新实验结果另列。有限模拟验证也不能证明所有真实 AGN 都适用。

## 使用

在仓库根目录安装 `python -m pip install ".[test,build]"`，然后：

```powershell
python -m blr_rm gui
python -m blr_rm generate --config 2D/generate_clean.json --out run_clean
python -m blr_rm batch --config 2D/generate_noisy.json --count 10 --out run_batch
python -m blr_rm optimize --data run_clean --config 2D/mem_defaults.json --error-floor 0.05 0.05 --out run_mem
python -m blr_rm check --data run_clean --result run_mem
python -m blr_rm scan --data run_clean --grid 2D/scan_grid.json --error-floor 0.05 0.05 --out run_scan
python -m blr_rm report --data run_clean --result run_mem --out run_report
python -m blr_rm benchmark --profile validation --out validation_new
python -m pytest
python tools/build_windows.py
```

一维将配置路径改为 1D。输出目录须为新目录，保留原有可追溯结果。本轮不修改为自动覆盖。

## 提交与发布边界

建议单次提交源码、回归测试、spec 和本文；不提交 build、dist、原始大规模模拟、个人绝对路径、账号凭据。EXE 用 GitHub Release 分发。历史源代码许可证和署名仍待负责人确认，不能擅自添加 MIT 许可。旧收据不要删除或改成新版结果。

后续正式验证应固定协议，再覆盖多个随机种子、形态、采样、时长、噪声、缺测及像素；分别统计格式/前向通过率、数值收敛率、默认图稳定率、真值误差和运行时间。未收敛和失败对象保留在分母内。不要用真值给每例选参后，再把该误差当独立验证结果。
